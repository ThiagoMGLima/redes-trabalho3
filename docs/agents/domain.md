# Documentação de domínio

## Escopo e layout

A raiz do projeto é `Trabalho2/`. O layout é single-context:

- `GLOSSARY.md`: vocabulário do Trabalho 2.
- `docs/adr/`: decisões de arquitetura do Trabalho 2.

## Antes de explorar o projeto

Leia `GLOSSARY.md`, se existir, e os ADRs em `docs/adr/` que tratem da área em análise.

Se esses arquivos ainda não existirem, prossiga silenciosamente. A skill `/domain-modeling` os cria quando termos ou decisões forem efetivamente definidos.

## Vocabulário

Use os termos definidos no glossário ao nomear conceitos em issues, propostas, hipóteses e testes. Se faltar um conceito necessário, registre a lacuna para `/domain-modeling`.

## Conflitos com decisões existentes

Quando uma proposta contrariar um ADR, indique explicitamente qual decisão será reaberta e por quê, antes de substituí-la.
